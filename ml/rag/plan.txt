## 🐳 **Production-Grade Log RAG System Plan**

### **1. Architecture Overview**
```mermaid
graph TD
    Kafka[Kafka: raw_logs] --> Consumer[RAG Ingestion Consumer]
    Consumer -->|Batch & Deduplicate| Processor[Log Processor]
    Processor -->|Generate Embeddings| Model[Embedding Model]
    Model -->|Upsert Vectors + Metadata| Chroma[ChromaDB]
    
    User[User] -->|NL Query| API[RAG API]
    API -->|Hybrid Search| Chroma
    Chroma -->|Ranked Results| LLM[Ollama: Llama3/Mistral]
    LLM -->|Answer| User
```

### **2. Core Components & Tech Stack**
| Component | Choice | Rationale |
|-----------|--------|-----------|
| **LLM (Dev)** | **TinyLlama (1.1B)** | Extremely lightweight (~600MB), perfect for local dev testing without GPU. |
| **LLM (Prod)** | **Llama 3 (8B)** | Production-grade reasoning and instruction following. |
| **Embeddings** | **all-mpnet-base-v2** | Gold standard for semantic search. Maps log "meaning" well. |
| **Vector DB** | **ChromaDB** | Native Python integration, supports metadata filtering (crucial for logs). |
| **Ingestion** | **Kafka + Python Consumers** | Decoupled, scalable ingestion. |

### **3. Enhanced Data Strategy (Crucial for Logs)**

#### **A. Smarter Chunking**
Raw logs are noisy. Embedding every single line is inefficient and degrades retrieval quality.
**Strategy: `LogCluster` + Time Window**
1.  **Normalization**: Remove variable parts (dates, IPs, IDs) to find the "Template".
    *   *Raw*: `2023-10-27 10:00:01 Error connection failed to 192.168.1.1`
    *   *Template*: `Error connection failed to <IP>`
2.  **Aggregation**: Group logs by `(Source, Template, 1-Hour Window)`.
3.  **Chunk Content**:
    ```text
    Source: Payment-Service
    Time: 10:00 - 11:00
    Level: ERROR
    Event: Error connection failed to <IP>
    Count: 1543 occurrences
    Sample Variables: 192.168.1.1, 10.0.0.5
    ```
4.  **Embedding**: Embed the *Chunk Content* (Template + Summary). This allows the LLM to understand *patterns* rather than distinct events.

#### **B. Metadata Enrichment**
Store strict fields in ChromaDB metadata for **Hybrid Search**:
- `source_id`
- `log_level` (INFO, ERROR, WARN)
- `service_name`
- `timestamp_hour`

### **4. Implementation Steps**

#### **Phase 1: Infrastructure (Docker)**
1.  **Ollama Service**:
    - Mount volume `ollama_model_data` to reuse downloaded models.
    - Check for GPU support (`--gpus all`) if host allows, otherwise CPU.
2.  **Backend Updates**:
    - Add `chromadb`, `sentence-transformers`, `ollama` python clients.

#### **Phase 2: Data Ingestion Pipeline**
1.  **Consumer (`server/consumers/rag_ingestion.py`)**:
    - Buffer logs for `N` seconds or `M` size.
    - Implement simple Clustering/Templating (Regex or simple string masking).
    - Upsert to ChromaDB:
        - `id`: `source_{id}_{hour}_{template_hash}` (Deterministic ID allows easy updates).
        - `embedding`: Vector of the Template.
        - `metadata`: `{ "start_time": ..., "count": ..., "level": ... }`.

#### **Phase 3: Retrieval & Query Engine (The "Brain")**
1.  **Query Pre-processing (LLM)**:
    - Convert User NLQ -> Structured Filter.
    - *User*: "Show me errors in payment service last 2 hours"
    - *LLM Output*:
      ```json
      {
        "filter": { "source": "payment", "level": "ERROR" },
        "time_range": "2h",
        "semantic_query": "errors failure exception"
      }
      ```
2.  **Hybrid Search**:
    - Query ChromaDB with: `where={"level": "ERROR"}` AND `query_texts=["errors failure exception"]`.
    - Retrieve Top-20 Chunks.
3.  **Context Construction**:
    - Format chunks into a readable prompt context.
    - *Prompt*: "Analyze these log summaries. Count is frequency. Answer the user question."

#### **Phase 4: API & Feedback**
1.  **Endpoints**:
    - `POST /rag/query`: Streaming response.
    - `POST /rag/feedback`: User rates answer (Good/Bad) -> Store for fine-tuning.

### **5. Configuration Management**
- **Docker Compose**:
  - `OLLAMA_HOST=ollama`
  - `CHROMA_HOST=chroma`
  - `MODEL_PATH=/app/ml/models` (Cache models here to avoid redownload)

### **6. Important Instructions**
1.  **Environment Variables**: ALL tunable params (batch size, model name, confidence threshold) MUST be environment variables.
2.  **Error Handling**: If Ollama is down, fallback to keyword search or return graceful error.
3.  **Model Caching**: Download `all-mpnet-base-v2` and llm weights in `run.sh` or a setup script, NOT at runtime, to prevent timeouts.
