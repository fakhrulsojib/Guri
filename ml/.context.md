# 🧠 MACHINE LEARNING CONTEXT (.context.md)
> **Goal:** Define core architectural boundaries, pipelines, and rules for the Python Machine Learning services (Anomaly Detection & RAG).

## ⚙️ Tech Stack
| Category | Technology |
|---|---|
| Language | Python 3 |
| Anomaly Detection | `pyod` (IsolationForest), `scikit-learn`, `pandas`, `numpy` |
| RAG Engine | `chromadb` (Vector DB), `sentence-transformers` (Embeddings) |
| LLM Service | `ollama` (TinyLlama for Dev, Llama 3 for Prod) |
| Async/Streams | `joblib`, `confluent-kafka` |

## 📐 Architecture Rules
- **Model Training & Persistence:** Use `joblib` for persisting and loading generic `scikit-learn` or `pyod` trained pipelines (e.g., in `/ml/anomaly_detection/models/`).
- **RAG Data Strategy:** Do not embed single noisy log lines. Normalize, template, and cluster logs (e.g., 1-Hour Windows) before generating embeddings and storing in ChromaDB.
- **RAG Metadata:** Heavily rely on ChromaDB's metadata filtering (e.g., `source_id`, `log_level`, `timestamp_hour`) to support Hybrid Search before passing context to the LLM.
- **Environment Management:** Rely entirely on environment variables (e.g., `OLLAMA_HOST`, `CHROMA_HOST`, `MODEL_PATH`) for tunable parameters and external service resolution.

## 🚫 Constraints (AI Rules)
- Do NOT download models explicitly at runtime on every application start; models must be cached via volumes (e.g., `ollama_model_data`).
- Do NOT perform heavy ML inference within the core CRUD FastAPI API threads; keep ML isolated or asynchronous.
- Do NOT create monolithic scripts. Maintain clean separation between `DataLoader`, `FeatureEngineer`, `Model`, and `Pipeline` objects.
- Do NOT assume the availability of a GPU environment; gracefully fallback to CPU configurations unless explicitly `--gpus all` is provided and supported by the host.
