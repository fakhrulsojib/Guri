# 🐘 BACKEND CONTEXT (.context.md)
> **Goal:** Define core architectural boundaries, API strategies, and rules for the FastAPI Server application.

## ⚙️ Tech Stack
| Category | Technology |
|---|---|
| Framework | FastAPI, Uvicorn, Python 3 |
| Database | PostgreSQL, asyncpg (HTTP pool), psycopg2 (consumers) |
| Data Validation | Pydantic v2 |
| Streaming/Async | Confluent Kafka, WebSockets, AnyIO |

## 📐 Architecture Rules
- **API Design:** Adhere heavily to FastAPI dependency injection (`Depends()`) for database sessions, current user extraction, and common request validations.
- **State Management / Data Flow:** Controllers (routers) handle HTTP lifecycle and invoke Service functions. Service functions hold business logic and call Repository/Model layers. All HTTP-facing DB calls use the async `asyncpg` connection pool; background Kafka consumers use synchronous `psycopg2`.
- **Error Handling:** A global `@app.exception_handler(Exception)` in `main.py` catches all unhandled exceptions, logs full tracebacks via `structlog`, and returns clean 500 JSON responses. Raise `HTTPException` for standard protocol errors (4xx).
- **Validation Boundaries:** Utilize Pydantic rigorously for both request parsing and response serialization. Never pass untrusted raw dicts directly into database queries.

## 🚫 Constraints (AI Rules)
- Do NOT assume Django, Flask, or WSGI synchronous patterns. Use FastAPI's `async def` for I/O bound operations.
- Do NOT use synchronous `psycopg2` in HTTP handlers. All HTTP-path DB access MUST go through the async `asyncpg` pool helpers in `database/database.py`.
- Do NOT skip Pydantic validation for any input data mapping.
- Do NOT mix heavy machine-learning inference pipelines directly into the core CRUD server; delegate those to the `/ml` service boundaries.
- Do NOT manipulate Kafka consumer/producer initialization without ensuring thread safety and proper asyncio lifecycle management.
