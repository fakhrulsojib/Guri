# 💻 FRONTEND CONTEXT (.context.md)
> **Goal:** Define core architectural boundaries and rules for the React/Vite Frontend application.

## ⚙️ Tech Stack
| Category | Technology |
|---|---|
| Framework | React 18 (Vite 5), TypeScript (strict) |
| State Management | Redux Toolkit, React-Redux, Redux Persist |
| Styling | Tailwind CSS |
| Routing | React Router DOM v6 |
| Testing | Vitest, React Testing Library, jest-dom |
| Linting / Formatting | ESLint, Prettier |
| Import Aliases | `@/*` → `src/*` (via `vite-tsconfig-paths`) |

## 📐 Architecture Rules
- **Component Pattern:** Functional components with hooks. Complex logic belongs in custom hooks (`src/hooks/`).
- **State Management:** Redux Toolkit for global state (Auth, cached data). Local `useState` for UI-only transient state.
- **API Error Handling:** Catch errors in Redux async thunks or custom fetch wrappers. Map HTTP errors to user-friendly messages. No silent failures.
- **Styling Strategy:** Tailwind CSS utility classes only. Avoid custom CSS unless strictly necessary for complex animations.
- **Error Boundaries:** `GlobalErrorBoundary` wraps `<App />` in `main.tsx` to catch rendering crashes.
- **Imports:** Use `@/` path aliases (e.g., `@/components/Header`) instead of deep relative imports.
- **Testing:** Use Vitest with `vi.fn()` for mocks (not Jest). Test setup in `src/tests/setup.ts`.

## 🚫 Constraints (AI Rules)
- Do NOT use Next.js features (App Router, Server Components) — this is a Vite CSR app.
- Do NOT mutate Redux state directly. Use Redux Toolkit `createSlice` reducers (Immer).
- Do NOT introduce new UI component libraries (MUI, Chakra, etc.) without verifying project standards.
- Do NOT use `jest.fn()` in tests — use `vi.fn()` from Vitest.
